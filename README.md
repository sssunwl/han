# 遊戲間

給小孩玩的網頁小遊戲集。線上版:https://sssunwl.github.io/han/

第一款是**方塊世界**(Minecraft 風格沙盒,目標對象小學四年級)。目前有六款:溫泉旅館(經營)、方塊世界、彈珠台、章魚燒、畫 Pizza、疊漢堡,全部可以離線玩。

## 溫泉旅館(`games/onsen/`)— v2 自由建造版

2.5D 像素經營遊戲,玩法參考開羅系(《溫泉物語》那類)。2026-10-24 從 v1「固定 11 格」改成**自由建造**:SS 反映 v1 蓋滿升滿就沒事做、一直說和室不夠又不能擴建。

**畫面**:俯視斜 3/4 像素,2026-10-24 起全部是自己的 Pixelkit(`shared/pixelkit/`)。開羅那種斜 45 度叫**等角(isometric)像素**,要另外畫一套等角素材才做得到 → 排在第二期。

**玩法**
- **土地**:32×24 格,切成 4×3 塊(每塊 8×8)。開局兩塊,之後一塊一塊買(價錢 ×1.55、要星級)
- **自由建造**:10 種設施(和室、大和室、大浴場、露天風呂、家族風呂、足湯、食堂、土產店、休憩室、卡拉OK),想蓋哪就蓋哪;門會自動開在離大門最近、走得到的那一邊;會擋住別人的門或櫃台的位置不准蓋。每種 3 個等級,可以拆除(退一半)
- **擺設**:11 種家具放在走道上,附近 2 格內的設施客人更滿意(加總的一半,最多 +10)
- **組合**(7 種,發現時口碑 +20):庭景和室、秘湯、溫泉街、湯上り處、足湯廣場、燈籠祭、金魚大廳。提示在「圖鑑」
- **研究**:客人退房給 💡 靈感(1~2 點,雜誌記者 3 倍)。17 項:解鎖新設施、新家具,或被動強化(接待、清潔、水質、料理、特產、寢具、宣傳、夜間營業)
- **員工**:退房後房間會變髒,員工去打掃(挑最近的),沒打掃好就不能住 → 要請人;每人每天薪水 ¥30,上限 = 1 + 星數
- **宣傳**:6 種,3 天內指定客群變多或每天多 3 人
- **客人**:5 種(家族、情侶、上班族、外國旅客、長輩),各有最愛的設施;家族 3~4 人要大和室
- **目標**:五星 → 每 28 天一年的**全國溫泉旅館排行**,拿到第 1 名
- 四季、隨機事件、天氣、日夜、評語跟 v1 一樣

**平衡是自動玩家跑出來的**(每天自動研究、請人、蓋房、買地、升級、擺植物,連跑 56 天):第 8 天 2★、第 26 天 5★,第一年年底全國第 5 名、第二年年底第 1 名。調的過程中踩過的坑:
- 土地變大後客人整天都在走路,傍晚還沒玩到任何設施 → 走路速度 46→72、一天 110→140 秒
- 每個人都 5 星、設施等級沒差 → 同一位客人第 n 項活動的開心程度 ×0.75^n
- 員工都去打掃清單第一間、橫越整張地圖 → 改去最近的
- 研究太少,靈感累積到上千沒地方用 → 加 8 項被動研究、靈感改成每人 1~2 點

**v2.1(2026-10-24 第二輪)加的**
- **成就** 25 個(有金錢/靈感獎勵),在「📊 經營 → 成就」
- **人生選擇** 13 種事件(颱風、明星包場、員工加薪、買源泉、網紅、料理比賽、收養看板貓…),約 3 成機率在早上跳出。選擇會留下永久效果(源泉、看板貓、加薪)或幾天的加成,並累積成「人情派 / 生意派 / 傳統派」的旅館風格。小神社會讓賭運氣的選項成功率 +15%
- **看得到的對手** 12 間有名字的旅館,每天自己成長;偶爾有新聞(開新設施、上電視)→ 那間成長變快,而且搶走你 2 天的客人。年底排行就是這張表
- **經營報表**:入住率、每天收入與入住率長條圖、客人類型、最受歡迎的設施、「客人希望有…」(還沒蓋的設施被許願幾次)
- **新設施 6 種**(溫泉蛋攤、遊戲機台區、茶室、按摩室、錦鯉池、小神社)、**新擺設 5 種**(行燈、竹叢、石燈籠、暖爐、鯉魚旗)。(當時 LimeZu 沒有的石燈籠、竹、鯉魚旗等用 `proc.js` 程式畫;v2.2 起全部改用 pixelkit)
- **客人小願望**:入住時會說想去哪,有蓋就優先去、滿意度 +8(願望實現),沒蓋就記到報表
- **配樂**:`shared/music.js` 用 WebAudio 即時合成 4 首日式 8-bit 曲(溫泉街、夜櫻、祭典、雪見),五聲音階 + 固定種子旋律,沒有音檔。預設「自動」依季節換曲、晚上換夜曲;🎵 可以選曲、關音樂、關音效(設定存在裝置,所有遊戲共用)
- 平衡(自動玩家 56 天):第 30 天五星;第一年年底第 5 名,第二年年底第 2 名(第一名只領先一點,玩得好可以超車)

**操作**:一指拖曳、兩指縮放(電腦用滾輪)、右上 ＋/－;擺放時點地圖換位置,綠框才能蓋。橫放手機時選單在右側,不擋地圖。

**存檔**:`onsen:<玩家>:save2`(v1 的 `save` 格式不相容,開始畫面會提示要重開)。開發時 `window.ON` 有 `advance / place / buy / research / hire` 等掛勾可以寫自動測試。

**檔案**:`data.js` 所有數值(調平衡只改這裡);`main.js` 格子/尋路/門、客人與員工狀態機、組合、繪圖、介面。

**v2.2(2026-10-24)美術全面換成自己的 Pixelkit**
- 家具、地板全部改用 `shared/pixelkit/japanese.js`(和風組 68 件,程式畫,畫風同雪糕店那批:3/4 俯視、32px 格、自動描外框、光從左上三階)。名字與尺寸沿用舊版,存檔裡的擺設直接對得上、擺放座標不用改
- 人物改用 `shared/pixelkit/character.js` 的 Q 版小人(24×32)。客人用數字決定長相(舊存檔的 1~12 也能用);員工每種職業固定髮色 + 制服色(打掃=棕髮綠衣、接待=黑髮粉衣、廚師=紅髮白衣、湯守=金髮藍衣,寫在 `data.js` 的 `STAFF_ROLES.look`),髮型每人不同;櫃台老闆娘是包包頭紫衣
- 泡湯只露頭肩;按摩床上躺著蓋毛巾;和室睡覺時頭靠枕頭、被子蓋到下巴;食堂後排客人夾在坐墊跟桌子中間
- 拿掉 LimeZu 素材:`public/onsen/atlas.*`、`tools/onsen_atlas.py`、`proc.js` 都刪了

## 做食物系列:章魚燒 / 畫 Pizza / 疊漢堡

2026-10-23 加的三款,玩法參考 SS 收藏的日本網頁小遊戲合集,**圖、音效、程式全部自己做**(canvas 畫、WebAudio 合成),沒有任何外部素材,所以沒有版權問題、也能離線。共用 `shared/kit.js`(音效、canvas 尺寸、存檔、相簿)與 `shared/food.css`(開始畫面/HUD/工具列)。

| 遊戲 | 玩法 | 存什麼 |
|---|---|---|
| `games/takoyaki/` 章魚燒 | 同一個洞一直點:倒麵糊 → 放章魚 → 翻面 → 夾起來。圈圈綠了動手最好吃。做滿 8 顆進入淋醬(醬汁/美乃滋/海苔/柴魚) | 各自的相簿 + 做過幾盤 |
| `games/pizza/` 畫 Pizza | 塗醬、撒起司、放 6 種配料,按烤看起司融化,烤好自動切片並依配料取名字 | 各自的相簿 |
| `games/burger/` 疊漢堡 | 食材左右擺動,點一下掉下去,偏太多會滑掉。掉 3 次或按「蓋上」就完成 | 共用排行榜 `burger:best` |

設計上的取捨:
- **沒有失敗到零**:章魚燒生的/焦的還是章魚燒,只是星星少;疊漢堡掉 3 次也會自動蓋麵包,一定拿到一個漢堡
- **疊漢堡的容許偏移是實測調的**:原本 0.62 倍兩者平均寬,結果擺動範圍內永遠不會掉;現在是較窄那層的 0.4 倍,隨便亂點約一半會掉
- **擺動幅度有上限**(1.3 個漢堡寬),不然手機橫放時食材會橫越整個寬螢幕
- **相簿存 220px JPEG、每人最多 6 張**,localStorage 存不下就自動少存,不會讓遊戲壞掉
- 手機橫放(高度 ≤ 540)時工具列移到右側直排
- 開發時窗格在背景 `requestAnimationFrame` 不會跑,三款都有 dev 限定的 `advance(秒)` 掛勾(`window.TK / PZ / BG`)可以快轉測試

## 彈珠台

`games/pinball/`。三台機台、過關解鎖、跨玩家排行榜。

**要加新機台**:在 `tables.js` 最下面多加一筆資料就好(擺設、配色、過關分數),外殼與物理是共用的。

### 物理

2D:球對線段、球對圓、旋轉擋板。每幀切 6 個子步進,避免高速穿牆。擋板的「打擊力道」來自接觸點的線速度 ω×r。

踩過的坑,都寫在程式碼註解裡:

- **通道要等寬**。上方導軌的內外壁一定要共用圓心,半徑固定差 30。圓心不同的話尾端會被夾到剩 17,球(直徑 18)當場卡死
- **下方導板斜度要夠陡**,否則導板與彈射器之間只剩 20 寬,球會楔在那裡
- **不要做發球道閘門**。球一旦從檯面繞回導軌就會坐在關起來的閘門上永遠出不來。拿掉之後改成「滾回發球道就重新發射」,反而更像真機台
- **導軌與外框之間的死角要封**,否則球會一直漏回發球道,一局重發二十幾次
- **子步進中球可能被判失球**,每一步都要重新確認 `ball` 還在,不然直接崩潰

### 數值是實測出來的

發球力道的可用區間很窄:1180 以下翻不過導軌,1350 以上球直接砸到左牆。所以蓄力對應的是「球會落在哪」——輕點落在右邊保險桿區,蓄滿橫越到左半場。

過關分數目前是 20,000 / 30,000 / 50,000,是拿自動測試腳本跑出來的參考值(腳本大約打 15,000～55,000)。**這組數字要等真人玩過再調**,改 `tables.js` 裡的 `goal` 一個數字就好。

### 給小孩的調整

- **開局護球**:每顆球前 9 秒掉下去直接還你。小孩最常見的挫折是「一發球就掉了什麼都沒做到」
- **卡住自動解除**:球在任何角落停超過 1.6 秒就往檯面中央推一下

### 比分數

排行榜存在 `pinball:best`,是**所有玩家共用一份**(跟各自的存檔分開),所以同一台裝置上大家的分數排在一起比。
**跨裝置比不了** —— 那需要一台伺服器,現在整個站是純靜態的。

## 為什麼不做登入

小孩記不住密碼,而且向未成年人收集帳號 / email 是個人資料的雷區 —— 一旦有帳號系統,就要處理同意書、資料刪除、外洩責任。

所以這裡只做「在這台裝置上選自己是誰」:

- 沒有密碼、沒有伺服器、沒有任何資料離開這台電腦
- 每個玩家的存檔用 `kidcraft:<玩家id>:world` 分開,互不干擾
- 代價:**換一台電腦就看不到自己的作品**。真的需要跨裝置,再做「匯出存檔檔案」比做帳號系統划算得多

## 給小四生設計,要考慮什麼

依重要性排序。這份原型已經照這些原則做了取捨。

### 1. 先砍掉「會讓小孩卡住」的東西
小四生的挫折容忍度很低,一卡住就不玩了。真正的 Minecraft 難的不是操作,是**生存壓力**。所以先拿掉:

| 拿掉 | 原因 |
|---|---|
| 血量、飢餓、怪物 | 死亡 = 進度損失 = 哭 |
| 合成表 (crafting) | 要背配方,是純記憶負擔 |
| 挖礦耐久、工具等級 | 增加規則但不增加樂趣 |
| 摔落傷害 | 小孩最常做的事就是從高處跳下來 |

剩下的核心迴圈只有兩件事:**挖掉方塊 / 放上方塊**。這個迴圈本身就夠好玩,Minecraft 創造模式賣的就是這個。

### 2. 操作要能在 30 秒內學會
- 只用左鍵挖、右鍵放、WASD 走 —— 沒有第七個按鍵
- 方塊種類控制在 **8~10 種**(這版 9 種)。太多會挑到麻痺,太少沒有創作空間
- 快捷列直接顯示中文名字 + 顏色,不要只有圖示
- **自動踏上一格台階**:這是最有感的一個調整。原版走路撞到 1 格高的地形要跳,小孩會一直卡在小土堆前面

### 3. 3D 暈眩是真的問題
小學生比大人更容易 3D 暈:
- 視野 FOV 固定 75,不要動態縮放
- 不做走路的鏡頭上下晃動 (head bob)
- 滑鼠靈敏度偏低
- 如果小孩會暈,退路是改成**第三人稱**或固定俯視角

### 4. 存檔一定要自動
小孩不會記得存檔,關掉分頁 = 心血沒了。這版每 10 秒 + 暫停 + 關頁面都自動存到瀏覽器 localStorage。
**注意:localStorage 換裝置/清瀏覽器資料就沒了**,如果他真的蓋了很得意的東西,要另外做「匯出檔案」。

### 5. 目標感 vs 純沙盒
純沙盒有些小孩會問「那我要幹嘛?」。低成本的解法(還沒做):
- 開場給一句任務:「蓋一間有門有窗的房子」
- 世界裡放幾個現成地標(山洞、大樹、小島)讓他有地方去
- 拍照鍵,存下自己的作品

### 6. 安全:不要做線上多人
一旦有多人 + 聊天,就要處理陌生人接觸、霸凌、內容審核 —— 這是完全不同量級的工程與責任。
要多人的話,先做**同一台電腦分享畫面**,或只開放給認識的人的房間碼。

### 7. 裝置:先決定鍵鼠還是平板
這版是 **PC 鍵盤滑鼠**。平板要另外做搖桿 + 觸控挖放,是額外一整塊工作,不要一開始就兩個都要。

## 任務系統(第二輪加的)

純沙盒有些小孩會問「那我要幹嘛」。設計原則:

- **一次只給一個任務**,不要任務清單。清單會讓人焦慮,單一目標才會動起來
- **每個任務都必須能自動判定完成**,不能靠小孩自己按「我做好了」
- 任務順序 = 教學順序,每一關偷偷教一個操作:

| # | 任務 | 偷偷在教 |
|---|---|---|
| 1 | 放下你的第一個方塊 | 右鍵 |
| 2 | 挖掉 5 個方塊 | 左鍵 |
| 3 | 蓋一座 4 格高的塔 | 往上疊(垂直思考) |
| 4 | 幫自己蓋一個屋頂 | 空間感:頭頂也是一個位置 |
| 5 | 蓋一間不漏光的小房子，然後站進去 | 密閉空間 = 前面全部技巧的組合 |
| 6 | 放 10 個彩虹方塊 | 純獎勵,發洩創作慾 |
| 7 | 自由創作 | — |

判定方式:
- 1、2、6 靠計數器
- 3 在放方塊當下算同一格垂直方向的連續長度
- 4 檢查玩家頭頂 1~4 格內有沒有「自己放的」方塊
- 5 從玩家腳下的空氣格做**洪水填充**,填不出去(320 格內、半徑 11 內)就是密閉;另外要求邊界至少 6 格是玩家自己放的,避免躲進天然山洞就過關

完成回饋要大:置中橫幅 + 彩帶 + 上升音階(音效是 WebAudio 合成的,沒有音檔)。挖/放也各有一個很短的音,手感差很多。

## 手機 / 平板

大部分小孩用手機玩,所以觸控是獨立的一整套操作,不是把滑鼠事件轉個彎:

- 左下**搖桿**走路、畫面上**滑動**轉視角、右下**挖 / 放 / 跳 / 飛**四顆鍵,快捷列可以直接點
- 挖鍵按住會連續挖(每 0.26 秒一次),小孩不用狂點
- 電腦端的滑鼠事件在觸控裝置會整組讓開,否則相容性滑鼠事件會讓視角轉兩倍

### 怎麼讓它不會跑掉出遊戲畫面

這是手機上最容易毀掉體驗的一件事,分四層處理:

1. `touch-action:none` + `overscroll-behavior:none` + `position:fixed` —— 擋掉捲動與下拉重整
2. 攔截 `gesturestart` / `contextmenu` / `dblclick` —— 擋掉雙指縮放、長按選單、雙擊放大
3. **全螢幕**:按「開始玩」時要求 `requestFullscreen()`(含 webkit 前綴),另外有一顆 ⛶ 切換鈕。電腦與 Android 都適用
4. **版面用 `100dvh`,不是 `100vh`**。`vh` 算的是工具列收起來後的高度,手機工具列還在時,底部的快捷列與動作鍵會被蓋掉。canvas 也改成 `position:fixed; inset:0` 由 CSS 撐滿,JS 用 `setSize(w, h, false)` 只調繪圖緩衝
5. **iPhone 只能靠「加到主畫面」**。iOS Safari 沒有全螢幕 API,只有從主畫面圖示啟動(`apple-mobile-web-app-capable`)才會沒有網址列、沒有左滑返回。偵測到這種情況時,開始畫面與大廳都會直接把步驟寫出來

### 效能

手機的 `devicePixelRatio` 常常是 3,照著畫等於多算 9 倍像素 —— 這是行動裝置掉幀最常見的原因。觸控裝置一律把 pixelRatio 壓到 1.5。

快捷列格子用 `clamp()` 跟著螢幕寬度縮,窄機(iPhone SE 橫放 667×375)才不會被右下動作鍵壓到而誤觸。已在 568×320 / 667×375 / 844×390 / 1024×768 量過四組座標,確認沒有互相重疊。

## 上線給小孩玩

這是**純靜態網站**,`npm run build` 出 `dist/` 丟上去就好,沒有後端、沒有伺服器成本。

- 世界是在小孩的瀏覽器裡即時產生的,網路只影響「第一次載入」,玩起來不會有延遲
- 存檔在各自瀏覽器的 localStorage,小孩之間不會互相蓋掉
- 目前規模(80×80×40、約 2.4 萬個面)對顯示卡是很輕的負擔;真正會卡是在舊平板或世界放大到 256×256 以上(那時要做 chunk 動態載入)

部署走 GitHub Actions(`.github/workflows/deploy.yml`):push 到 main → 自動 build → 發到 Pages。

兩個踩過的坑:
- `vite.config.js` 的 `base` 必須是 `/han/`,因為 Pages 是子路徑,不設資源會 404
- Pages 的來源要設成 **GitHub Actions**(不是「從分支部署」),否則 workflow 不會生效

大廳跟遊戲是分開的 entry,three.js 只在進遊戲時才載:大廳 gzip 約 3KB,遊戲約 136KB。

## 大廳:機舖風格

機台螢幕是每款遊戲的**真實畫面**(`public/lobby/*.png`,240×150、量化成 96 色,全部約 50KB)。重拍方式:開 dev server,用各遊戲的 dev 掛勾(`window.TK / PZ / BG / PB / KC / ON`)擺好畫面,把 canvas 縮成 240×150 存檔;遊戲畫面改很多時再重拍。

2026-10-24 改成電玩間(機舖)的感覺:深色背景配透視格線地板、霓虹招牌、PLAYER SELECT 選角色(選中的會跳、標 1P)、每款遊戲是一台機台(招牌、映像管掃描線、搖桿按鈕、INSERT COIN),點下去有投幣音效。
沒有用外部字型(離線要能用),像素感靠粗字 + 字距 + 霓虹光暈。開了「減少動態效果」的裝置會關掉動畫。

## 離線玩(飛航模式)

整站是 PWA:第一次連網打開後,所有遊戲都會被 Service Worker 存進手機,之後**加到主畫面**再開,飛航模式也能完整玩。

- `sw-template.js` 是範本,`npm run build` 時 `vite.config.js` 裡的小 plugin 會掃 `dist/` 全部檔案填進清單,輸出 `dist/sw.js`。**加新遊戲不用改 SW**,只要在 `vite.config.js` 的 input 加一行
- 快取版本號 = 所有檔案內容的雜湊,有任何改動就自動換新版、刪舊快取,不用手動改版本號
- 快取優先:有網路也先讀手機裡的,所以更新會在「下一次打開」才生效
- `shared/offline.js` 負責註冊,只在正式版註冊(dev server 不註冊,免得改程式看不到)
- 本機測離線:`npm run build && npm run preview`,開一次後把 preview 關掉再重整,每頁都應該還開得起來

新遊戲點子在 `IDEAS.md`。

## 技術筆記

- `main.js` 單檔,three.js + vite
- 方塊資料是一個 `Uint8Array`,索引 `(y*WZ + z)*WX + x`
- 畫面用 chunk(16×16)分塊建 mesh,只產生**外露的面**;改一個方塊只重建附近的 chunk
- 霧的範圍要大於世界對角線的一半,否則中距離地形會褪成天空色,看起來像破洞(踩過這個坑)
