# AI Star Builder v4 驗收報告

已將主遊戲改成 32×48 格、每格 32px 的俯視辦公室,另加一列人行道及兩列車道。滿版地圖上方保留公司狀態、趨勢、目標及左側通知,下方提供六個按鈕,功能內容放入約 62dvh 的抽屜。900px 以上採右側 380px 抽屜,原本參觀其他公司的小畫布維持剖面呈現。

房間仍是 `S.floors` 的原索引,沒有改變房間能力、價格公式、練習容量、LEARNING 或 `noRest>=7`。新增配置只保存 x/y 與 land。擺放檢查土地、重疊、一格走廊、所有門口及大廳到街道的 BFS 通路,大廳固定在街道邊。新建、取消、長按 450ms 搬移與土地購買皆透過地圖操作;搬移確認前保留原位置,因此中途存檔仍完整。

人物共用 Grid、goTo 與 moveAgent,從人行道入內、經走廊和門口移動,播放約 28 秒一週。明星、員工、小助理、自薦者、星探候選、合作代表與來訪明星皆走同一通行表。上午目標使用既有 timeline.floorOf,午餐前往餐廳,晚上回宿舍或離開;外出者走到人行道邊緣,返程沿相同地圖進門。離開名單的訪客先走出,才移除畫面角色。無路時每次路線失敗只記一行 console.warn 並移至目標,不讓動畫中止。播放期間保留「看事件」,底部為「⏭ 跳過播放」,小助理教學排隊與開發版 AS 原有方法均保留。

## 檢查結果與限制

`node --check` 通過 games/aistar 全部 JS/MJS、studio.js、street.js 及自動玩家,共 11 個檔案。`node games/aistar/engine.test.mjs`、`node games/aistar/ui-smoke.test.mjs`、`node tools/aistar_autoplay.mjs migrate-test` 均通過。v1–v8 各遷移至 v9 再跑十週,0 錯誤;20 房間舊檔保留房型、等級、明星與金錢,無重疊且每個門口 BFS 可達,另外亦以大廳加十九間 6×5 攝影棚檢查最大房間配置。

正式建置使用 `../han/node_modules/.bin/vite build --configLoader runner --outDir /tmp/aistar-v4-final`,成功。建置僅有專案既有的大型 kidcraft chunk 提示,輸出位於 /tmp。

手機版面採 375×812 對應的滿版 CSS 與起始 16 格寬縮放,介面測試驗證樣式存在、六鍵、各抽屜、建造確認/取消、買地、長按搬移、人物分步位移、外出/返回及舊功能操作。這些是假 DOM 與純邏輯驗收,不是實機視覺或觸控驗收;375×812、瀏海安全區、桌面抽屜遮擋及雙指縮放手感仍需人工檢視。抽屜拖曳收起由上方把手操作。

搬移房間後,若新牆剛好涵蓋某個正在走路的人,會觸發規定的無路徑後備;搬移確認的假 DOM 案例有出現一行警告,人物仍能繼續行動。房內站位與家具依房間尺寸重排,不同等級仍增加家具,但尋路目前將家具視為裝飾,只阻擋牆;多人可能共用站位或互相穿過。訪客先沿街道人行道尋路至邊緣,再走到 x=-24 的畫面外;返程先走回第一格,再沿 BFS 路徑進門。完整播放已在假 DOM 推進驗證,仍需人工觀看每日短時段切換時人物是否有足夠時間抵達餐廳、午餐後工作位置與宿舍;每個時段約半秒至一秒,距離較遠的角色可能仍在途中。這些呈現限制不影響引擎結算,也不代表已完成手機視覺驗收。
